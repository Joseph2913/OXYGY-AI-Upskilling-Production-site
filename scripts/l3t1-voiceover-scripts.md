## Slide 6 — Concept: What is an AI workflow? (`concept`)
**File:** `l3t1-s06-setup.mp3`

Let's define it. At Level 2, you built agents — individual tools that handle one task reliably. At Level 3, you connect those agents into a workflow: a sequence of steps triggered by an event, passing outputs between stages, applying conditions, and routing results to the right place. Think of it this way — an agent handles a task. A workflow handles a process.

## Slide 7 — Concept: When does a workflow make sense? (`concept`)
**File:** `l3t1-s07-setup.mp3`

Not every task deserves a workflow — that would be overengineering. The test is straightforward: if this task ran a hundred times, would the right output look broadly the same each time? If yes, it's a workflow candidate. If the output depends heavily on context and judgment that changes every time, it's better handled by a person with AI as a thinking tool. Let's test that now.

## Slide 10 — RCTF: The Three Layers (progressive-reveal, 3 clips)

### 10a — Setup (Input Layer)
**File:** `l3t1-s10-setup.mp3`

Let's explore each layer. First, the Input layer. Every workflow starts with two things: a starting event and the data it needs. That starting event could be a form submission, a file arriving, a scheduled time, or a message received. Without a defined trigger, the workflow has no way of knowing when to run. Nothing starts until the trigger is set. Click next to see the second layer.

### 10b — Reveal 1 (Processing Layer)
**File:** `l3t1-s10-reveal1.mp3`

Now the Processing layer. This is where the actual work happens. AI steps, conditional logic, and data transformations chain together to turn inputs into something useful. Think of it as the engine room — the AI reads a brief, checks a threshold, reformats data into a template. This is where input becomes output.

**~50 words**

### 10c — Reveal 2 (Output Layer)
**File:** `l3t1-s10-reveal2.mp3`

And finally, the Output layer. This is where results are delivered — either to a person for review, or directly to a destination. A well-designed output layer makes the final step as frictionless as possible. A document saved, a message sent, a manager review triggered, a record updated. Every workflow ends with something delivered.

## Slide 11 — RCTF: The Six Node Types (progressive-reveal, 6 clips)

### 11a — Setup (Trigger)
**File:** `l3t1-s11-setup.mp3`

Every workflow step is one of six types. Learn to recognise them and you can map any process. First up: the Trigger node. This is what starts the workflow — a user action, a schedule, an incoming event. No trigger means no automation. It's the first thing you define when mapping any workflow.

**~50 words**

### 11b — Reveal 1 (AI Action)
**File:** `l3t1-s11-reveal1.mp3`

Next, the AI Action node. This is the value step — where an AI model does the actual work. Classifying intent, summarising a document, drafting a reply. Whenever you see a step where the AI generates output, that's an AI Action.

**~40 words**

### 11c — Reveal 2 (Transform)
**File:** `l3t1-s11-reveal2.mp3`

Third is the Transform node. This reformats or restructures data between steps — extracting fields from text, merging two responses, converting a format. Transforms are the glue that connects one step's output to the next step's input.

**~37 words**

### 11d — Reveal 3 (Condition)
**File:** `l3t1-s11-reveal3.mp3`

Fourth, the Condition node. This routes the workflow based on a rule. If confidence is below eighty percent, escalate. Otherwise, continue. Conditions are what make a workflow adaptive rather than brittle — they let it respond to what it finds instead of following a single rigid path.

**~45 words**

### 11e — Reveal 4 (Handoff)
**File:** `l3t1-s11-reveal4.mp3`

Fifth is the Handoff node. This passes work to a human or another system — a manager review, a CRM update, a Slack notification. Handoffs are where human oversight and cross-system integration happen. They're deliberate design choices, not gaps.

**~40 words**

### 11f — Reveal 5 (Output)
**File:** `l3t1-s11-reveal5.mp3`

And finally, the Output node. This is the final result — the thing the workflow exists to produce. A drafted report, an approved response, an updated record. Every workflow should end with a clear, defined output. Those are your six node types — and together they can map any process.

**~48 words**

## Slide 13 — Concept: Handoffs (`concept`)
**File:** `l3t1-s13-setup.mp3`

Now let's talk about handoffs — the points where work passes from one step to the next. Handoffs create risk when they're implicit. If a step assumes the previous one completed correctly but there's no check, errors travel silently downstream. But handoffs create opportunity when they're explicit — a deliberate review catches errors before they matter, a conditional handoff routes high-stakes cases for approval. The goal isn't fewer handoffs. It's better-designed ones.
